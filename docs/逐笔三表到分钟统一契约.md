# 逐笔三表到分钟的统一契约

更新日期：2026-10-08。业务依据为冻结任务书V1.8。本文说明raw生成与分钟消费的
现行代码契约，来源是任务书、已验收候选及本轮补差；历史数据是否已发布为新口径，
必须另看逐日文件、成功质检和部署记录。

## 1. 两个框架如何衔接

| 对象 | 当前代码版本或契约 | 负责内容 |
| --- | --- | --- |
| raw转三表框架 | 1.2.0 | 原始事件映射、1/U定价片段、质量核验、按日三表发布 |
| Trans_To_Min | 1.1.0 | 物理读取、显式视图、分钟映射、共享I/O、来源契约与按月发布 |
| 报价语义 | price_policy_version=3 | 有效原价、实际成交片段价、可靠恢复价或NULL |
| 存储编码 | format_version=1 | 固定字段、缩放10000、午夜以来毫秒和类型编码 |
| 标准取数包 | research-toolkit 0.5.3 | 可作为独立读取对照；核心运行不依赖它 |

软件版本不用相等。两个框架对齐的是同一三表粒度、金额单位、时间、完整订单键和
NULL含义。raw项目不依赖分钟聚合，分钟项目也不重新实现raw定价算法。

```text
raw原始事件
  → 日频A股股票池、完整股票生命周期、唯一raw转换与质检
  → 委托片段 / 真实成交事件 / 真实撤单事件
  → Arrow物理Schema读取与单位还原
  → 业务显式选择事件、委托订单或成交参与订单视图
  → 固定242分钟映射、业务聚合、NULL与真空分钟补齐
  → 每指标四列月文件、来源契约和manifest
```

执行器在计算前后核对来源；日输入经核验且不可变发布是前提。框架不查询数据库，
也不能仅靠footer证明股票池、raw质量和生成凭证全部正确。

## 2. 三表真实粒度

| 市场及表 | 一行表示什么 | 时间、价格与数量 |
| --- | --- | --- |
| 深市委托 | 限价2原委托，或市价1/U逐成交片段与不重复余量片段 | 片段复制原委托时间；已成交片段使用对应真实价量；余量无可靠价为NULL |
| 沪市委托 | 原A事件，或缺A引用的一笔成交补单片段 | A保留自身时间、原价及旧数量；补片用对应成交时间和价量 |
| 深市成交 | 每次真实F/0成交 | 原成交时间、价、量、实际额、双号及主动side；重复内容的真实事件也保留 |
| 沪市成交 | 每次真实成交，含N方向 | 原事件时间；金额来自TradeAmount，不用挂单价重算 |
| 深市撤单 | 每次真实C/4撤单 | 本次撤单时间和量；限价用原价，1/U可靠恢复不足为NULL |
| 沪市撤单 | 每次真实D事件 | 本次D时间、自身原价和旧数量映射，不增加新的D/A改价关联 |

深市拆片量之和等于原委托数量；沪市缺A补片只能表示已观察成交部分，不能凭它
虚构原完整数量。若多条A实际是累计状态，必须先厘清来源，不能当增量相加。
储存排序键相同不代表重复；任何市场都不能按买卖订单号对、价格或毫秒删除成交。

## 3. 字段与读取

委托、撤单物理字段为
`symbol,date,time,order_num,channel,price,side,volume,type`；成交为
`symbol,date,time,buy_order_num,sell_order_num,channel,price,volume,money,side`。

- 股票代码保留`.XSHG/.XSHE`，日期date32，时间uint32表示当地午夜以来毫秒。
- 委托/撤单price为可空int64；成交price和money按生成端契约非空int64。
- price/money各按自己的metadata缩放。物理整数100000且price_scale=10000表示
  10元；是否缩放依据Arrow类型，含NULL后Pandas变为浮点不改变物理整数事实。
- 实际浮点价不重复缩放；整数缺scale、非法比例或所需字段缺失会报错。
- 委托/撤单没有物理money时逐片段派生`price × volume`，空价派生NULL。
  成交缺物理money明确失败，不允许用price×volume伪造实际成交额。
- 适配器保留原事件、空价、空额、双号及side；不猜价、填零、取绝对值、dropna或聚合。
- channel虽然可按需裁列，完整订单聚合或关联必须声明读取它；type编码按metadata还原。

生产路径为`/sd1-data/level2/{dataset}/{YYYY}/{YYYYMM}/{YYYYMMDD}_{dataset}.parquet`。
路径存在不证明文件已经采用报价3；不能按日期推断、给旧metadata补3或自动修旧源。

## 4. 三种视图明确选择

### 原事件视图

成交量额、事件笔数及撤单事件默认按自身真实时间归分钟。主动成交方向使用原
`side`，不根据新委托片段重新反推。委托也可由业务明确保留片段视图，但片段行数
不能未经声明称作完整订单数。

### 委托订单视图

`aggregate_order_fragments(frame, trade_date)`只在完整日或完整股票分区调用。
完整键是`trade_date,symbol,channel,order_side,order_num`；委托side就是订单方向，
逐日调用隐含日期。缺身份、空身份、非法时间或数量报错，不退回按行计单。

```text
锚点 = 全部合格片段最早时间
订单数 = 1
订单量 = 全部可相加片段volume之和
已知订单额 = 已定价片段price×volume之和；全部缺额则NULL
```

单、量、额同归锚点分钟，不使用首价乘总量，也不生成汇总均价。先切分钟、任意
Arrow批次、集合竞价或空金额再聚合，会改变完整订单，禁止当作整单视图。
视图无法恢复调用方事先删掉的片段，完整性由调用方保证；共享原表保持不动。

600股×10元和400股×10.01元组成一个1000股、10004元订单，而非两单或10000元。
最早200股缺价、后续300股10元时，订单数1、量500、已知额3000，锚点仍为最早片段。

### 成交参与订单视图

`trade_order_participation(frame, trade_date, order_side=..., time_scope=...)`明确选择
`buy/sell/both`与`per_minute/first_event`。买方1单对应卖方2单时，双侧为3单；
分钟参与允许同订单跨分钟再次出现，全日首次只归最早参与分钟。
参与订单侧别与原主动side独立。该视图不返回两腿量额，避免双计市场单边成交。
原成交表仍保留全部真实事件；撤单也不因委托锚点或参与视图被移动或去重。

## 5. 空额、已知零与真空分钟

| 最终业务统计组 | 金额结果 | 单数、量、时间 |
| --- | --- | --- |
| 有事件，全部缺额 | NULL | 正常使用完整合格事件 |
| 有事件，部分有额 | 累计已知部分 | 不因金额筛空改变 |
| 有事件，已知额为零 | 0 | 零是有效值 |
| 真正无合格事件 | 该指标原empty_value | 沿原指标定义 |

金额筛空只发生在金额分支。保留过滤前事件数、有效金额数及相关数量统计，不能将
筛掉全部缺额后的空表误判为真无事件。求和可用`sum(min_count=1)`；轨迹或极值
指标需要按自己的最终路径组恢复全缺额NULL。

`validate_amounts()`默认允许约定缺失，非空负额、Inf及非法数值仍报错；真实成交
应使用`allow_missing=False`。该函数须业务显式调用，不是适配器全局删行规则。
`MinuteMetric`补齐已有稀疏NULL时不会填成0；整数指标也使用可空整数保存业务NULL。
已知部分金额应称“已定价金额”，不应称完整订单/分钟金额。

## 6. 49项现有业务与生产门禁

| 业务 | 代码版本 | 指标数 | 委托口径 | 成交与撤单 |
| --- | --- | ---: | --- | --- |
| maxdiv | 0.2.0 | 27 | 9项完整订单、最早锚点后再连续竞价过滤 | 成交逐事件主动方向；撤单事件，3项金额支持NULL |
| entropy | 1.1.1 | 3 | 委托量熵按完整订单总量分布 | 成交、撤单量熵仍按事件分布 |
| time_center | 0.6.0 | 19 | 6项按完整订单量或一次计单加权 | 12项重心及cd_bv_min沿原事件 |

maxdiv买/卖极值来自同一有符号累计路径，不是买卖金额简单求和；该路径全缺额
才为NULL。三业务各3个物理I/O组，合计每天9次业务读取，不是整链仅3次。
同源组每表每天只读一次字段并集，然后分开事件、订单、方向和金额分支。

49项正式指标都显式声明`required_price_policy_version=3`及算法版本。新增业务需
维护README、generation_spec.json、独立预期和测试；在生产中通过单项或组执行器
运行。内存`compute_day()`没有文件身份，适合公式测试，不能证明真实来源已验收。
三业务模块名均为`minute_metrics`，分别从业务目录、独立进程启动；核心安装共享，
业务源码独立。业务wheel独立target/环境安装，不能三包混装后混合导入。

## 7. 发布与续跑契约

分钟文件维持242个上海时区结束标签、左开右闭特殊边界、四列
`trade_date,minute,symbol,{metric_name}`及每指标`{YYYY}/{YYYYMM}.parquet`。
本次不给实时信号保证：盘后恢复价和整单量额回归最早锚点可能含事后信息。

执行器的逐指标×日期契约包括输入路径、设备/inode、大小、mtime/ctime、行数、
Schema/metadata、核心及业务源码、算法声明和显式参数；自定义组公式也参加身份。
计算前后核对来源，期间变化拒绝发布。默认委派组与单项同口径可共用恢复凭证。
月份footer的`source_contracts`保留各日期摘要，增量/指定日重算保留其他日期的原凭证。

- 默认模式遇到待生成日期已存在就拒绝隐式覆盖。
- resume只跳过相同日期、来源和算法的已发布结果；缺凭证、旧/未知报价或身份变化报错。
- overwrite_dates只显式替换用户选定日期；未替换旧日不能凭空获得新来源凭证。
- 源文件须不可变发布。契约不扫描全部大文件内容，不防人为改内容后恢复所有stat。
- 代码要求实体模块源码；业务参数放入`contract_parameters`，不依赖隐藏实例状态。

旧结果不会自动修复。用户后续重建可先选全新隔离输出目录；需要覆盖旧结果时，
先审核逐日新源和指标×日期范围。未经审核，不伪造旧footer或仅因文件存在续跑。

## 8. 验证和此次边界

核心与三业务分别用pytest运行，不能只用unittest遗漏函数用例。合成测试覆盖缩放、
订单、NULL、字段并集、来源门禁、全量/增量/续跑和双进程；包测试必须核对实际
import来自独立wheel target，而非源码目录。
`scripts/verify_policy_v3_chain.py`用于明确授权的隔离真实样本，补齐物理Schema、
242标签、时区、日期、股票集合、唯一键、NULL及公式检查。参考公式不调用生产
订单视图/业务聚合，但仍复用适配器和分钟映射，因此不是完全独立的全链金标准。

2026-10-03的147项记录仍只覆盖三日六股。本次统一代码与文档不重新生成信息熵、
时间重心或其他历史分钟数据，也不修改raw公式、历史输入、日频因子和回测。
正式包、代码部署与已有结果来源分别记录，不能互相代替完成证据。
