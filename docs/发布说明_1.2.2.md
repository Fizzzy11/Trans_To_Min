# Trans_To_Min 1.2.2 发布说明

发布日期：2026-11-10。本次是默认收盘边界的小版本修正，不运行生产数据任务。

## 一、已实现的修改

`MinuteMetric.include_post_market`、`assign_minute_codes`、
`assign_timestamp_minute_codes`和`assign_minute_labels`的默认值从`True`改为`False`。
15:00结束标签只包含`(14:59:00.000, 15:00:00.000]`：

| 事件时间（Asia/Shanghai，毫秒精度） | 默认归属 |
| --- | --- |
| 14:59:00.000 | 14:59 |
| 14:59:00.001至15:00:00.000 | 15:00 |
| 15:00:00.001及以后 | 不参与分钟聚合 |

显式设置`include_post_market=True`仍可采用旧行为，把14:59之后的事件统一折入
15:00；不增加独立盘后分钟轴。业务若已有显式覆盖，框架升级不会强制改写该配置。

## 二、保持不变

- 固定242个分钟结束标签、左开右闭常规区间、盘前及午休特殊边界。
- 指标声明输入中实际出现股票的并集及242分钟补齐；只有盘后记录的输入股票也保留
  空分钟，真空分钟沿用指标的0或NULL规则，不查询额外股票池。
- 输入根目录`/sd1-data/level2`、默认输出根目录`/sd1-data/trans_to_min`。
- 正式层级`/sd1-data/trans_to_min/{主题}/{类别}/{指标}/{年份}/{年月}.parquet`；
  主题和类别仍由业务配置，每个指标独立四列长表，显式输出路径继续有效。
- raw定价、三表Schema、NULL金额、现有订单视图及channel键、并行与月度发布机制。
- 1.2.0的全量/日更/修订标准入口和来源门禁，不新增总调度器或定时任务。

## 三、自定义计算边界

适配器仍保留全日原始事件；基类在`prepare_events`之后映射分钟并筛掉无效编码，
不是在读取时统一删除盘后。若业务预先合并订单或把事件移动到更早锚点，必须自己
在预聚合／关联前筛选原始时间；映射默认值不能撤销已折入较早时间的盘后量额。
重写`compute_day`或自定义指标组计算的业务也须显式遵循并验证自身时间范围。
现有`trade_order_participation(time_scope="per_minute")`内部显式保留旧分组映射，
不因公共默认值变化提前丢掉纯盘后订单；交给基类时默认False会排除，显式True
仍能保留旧结果。直接消费视图的业务须自行筛选时间，订单键和统计公式没有改造。

此次同时发布[正常242分钟与四项基础数据目标规范](正常242分钟通道号与基础数据口径修订_20261110.md)，
明确去通道号以及`wt_basic_min`、`cd_basic_min`、`cj_basic_min`、`acj_basic_min`
四个独立业务任务仍待实施。该文档不证明其代码、机器规格、独立公式、安装及历史
结果已改造。1.2.2不实施这些业务变更，不修改已有信息熵、时间重心等任务公式。

## 四、升级与历史结果

含15:00之后事件且沿用默认值的指标，15:00结果可能与1.2.1不同。框架版本、源码
和分钟开关参与逐指标逐日来源契约；旧结果不自动获得新凭证，即使显式开启旧映射
也不能绕过版本门禁。仅追加新日不等于历史已验收，不允许擅自改写凭证或重算历史。

本次同步本地源码、服务器框架及GitHub版本和安装包；既有业务入口、生产目录权限、
数据迁移和历史重建均不在本次范围。部署前核对相关进程，保留明确文件清单与备份；
测试仅使用临时合成数据，结束后清理服务器本次测试临时目录。
