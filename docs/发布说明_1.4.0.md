# Trans_To_Min 1.4.0 发布说明（2026-11-13）

## 改了什么

此前每个已发布日期都在月文件footer（`source_contracts`）和manifest里存一个哈希凭证，
把来源文件身份、框架版本、框架全部源码、业务包全部源码和指标定义混在一起。任何一处
代码改动，包括不影响数值的调度、日志、注释修改，都会让全部已发布数据不能resume、
不能重新校验。

1.4.0取消这套已发布结果门禁：不再保存、读取或比对已发布结果的来源／代码哈希凭证，
数据由维护者自行管理。

这里不包括临时独立参考检查点：检查点仍绑定来源文件身份和参考代码摘要，失效时自动
重扫参考，避免复用过期参考值。这不会阻止历史结果resume，也不会自动重算已发布分钟数据。

| 项目 | 1.3.0 | 1.4.0 |
| --- | --- | --- |
| 月文件footer的`source_contracts` | 写入并核对 | 不写、不读 |
| manifest逐日条目的`source_contract` | 写入 | 不写 |
| `resume=True`对已发布日期 | 凭证一致才跳过，否则报错 | 日期存在即跳过 |
| `validate_published` | 先比凭证再比数值 | 只比结构和数值；报价版本门禁照常执行 |
| 计算前后来源文件是否被替换 | 检查 | 检查（仅本次运行内，不落盘） |
| `required_price_policy_version` | 检查 | 检查 |

manifest里的`framework_version`照常记录，可用于查询某次运行使用的框架版本。

## 已发布数据

无需任何处理，默认可信：

- resume请求到已有日期时直接跳过，数值不动；
- 往旧月文件追加新日期时，旧日期数值原样保留；
- 旧月文件footer里遗留的凭证不读不比，该月下次被重写（追加或重算日期）时自然消失；
- 重新校验只比结构和数值。

## 仍然会拦截的情况

- 计算期间来源文件变化：拒绝发布（“计算期间来源文件发生变化，拒绝发布”）。
- 指标声明了`required_price_policy_version`而来源footer不符：拒绝读取。
- 非resume、非覆盖模式下请求已存在的日期：拒绝运行，防止隐式覆盖。

## 不再拦截、由数据维护者负责的情况

- 修改了业务公式、参数或`algorithm_version`：框架不提醒。需要重建时用
  `overwrite_dates`显式重算受影响日期，否则同一数据内新旧口径混存。
- 框架升级改变了输出数值：框架不提醒。动到读源、分钟归属等核心逻辑后，建议抽取
  若干月份用`validate_published`对照独立参考重新校验。
- 来源文件在发布后被上游重新交付：resume不会发现，需要时显式重算对应日期。

## 兼容性

- `provenance.read_contracts`、`provenance.validate_resume`已删除；业务侧若直接调用需移除。
- `provenance.source_contract`签名不变（`group`参数保留但不影响结果），返回值仍是64位
  十六进制摘要，只用于运行内比较，不代表任何已保存的凭证。
- 分钟轴、公式、输出层级、四列Schema与发布逻辑不变。
