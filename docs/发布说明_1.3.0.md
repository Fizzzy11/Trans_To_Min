# Trans_To_Min 1.3.0 发布说明

发布日期：2026-11-12

## 一句话

源文件只从磁盘读一次：生成、独立参考校验、以及读取同一张逐笔表的其他任务，都从内存盘里
同一份字节解码。机制写在框架执行器里，业务任务不需要也不允许自己打开源文件。

## 为什么改

1.2.4 及以前，一个交易日的同一张逐笔表会被多次从机械盘读出：

- 生成读一次，生成结束后独立参考校验再读一次；
- 读取同一张表的不同任务（例如 cj 与 acj 都读成交表）各读各的；
- 多个进程同时读同一块机械盘时互相抢磁头，单流吞吐从顺序读的水平跌到每秒几兆到十几兆。

全量回填的实测瓶颈正是这块盘的并发读，而不是 CPU、内存或写入。

## 改了什么

### 1. `trans_to_min.source_stage`：按文件身份共享的内存盘暂存

- 暂存根目录默认 `/dev/shm/trans_to_min_stage_<uid>/`，可用环境变量
  `TRANS_TO_MIN_STAGE_ROOT` 或 `RunConfig.source_stage_root` 改到任意目录。
- 副本按文件身份（设备、inode、大小、mtime、ctime）命名。任何任务、任何进程请求同一个
  源文件，拿到的都是同一份副本；第一个请求者负责顺序读盘，其余等待后直接命中。
  **共享不依赖任务之间的任何约定**：两个任务读同一张表就自动共享，不读同一张表就各自
  暂存各自的文件，互不影响。
- 引用计数由内核 `flock` 承担：每个持有者在副本上保持共享锁；进程被 kill 时锁自动释放，
  不会留下需要人工修正的计数。
- 同一块机械盘（`rotational=1`）上的读取用设备级排它锁串行化，保证磁头只做顺序读；
  固态盘不加这把锁。
- 从源盘抄入暂存时用 `O_DIRECT` 每次 32M 的大块读（文件系统不支持时自动退回普通读）。
  机械盘上有其他进程读写时，普通读每个 128K 预读窗口之间都会被插队；本服务器实测
  普通读 15–19 MB/s，大块直读 54–72 MB/s。
- 预算 `RunConfig.source_stage_budget_gb`（默认 48G）：超出时先淘汰无人持有的最旧副本，
  仍放不下则退回进程私有内存副本（`buffer`），结果不变，只是不共享。
- `RunConfig.source_stage_retain`：
  - `False`（默认）：最后一个持有者释放时立即删除副本；
  - `True`：释放后保留，供稍后读取同一文件的其他任务命中；由调度器在批次结束时调用
    `source_stage.clear()` 清空。
- `RunConfig.source_stage="off"` 恢复 1.2.4 的直接读盘行为。
- 调度器接口：`stage_files(paths, **options)` / `release(handles)` / `sweep()` / `clear()`。
  日频阶段上百个任务读同一天三张表时，调度器先 `stage_files` 持有当天三张表，全部任务结束后
  `release`，磁盘上每张表只读一次。

### 2. 执行器改造

- `MinuteMetricGroupRunner` 与 `MinuteConversionRunner` 的日期进程统一通过
  `source_stage.acquire` 取得句柄，再交给 `L2InputAdapter.read(..., source=handle)` 解码。
- 父进程内的 `Prestager` 按日期顺序提前把后续若干天的源文件读入暂存（窗口为
  日期进程数加 2），日期进程开工时直接命中；解码计算与读盘重叠进行。
- 解码前后核对源文件身份，读取期间源文件被替换即报错。
- 来源契约、月文件 Schema、分钟轴、公式、发布与续跑逻辑不变。

### 3. `trans_to_min.reference_check`：生成期顺带算独立参考

- 业务提供 `DayReference(function, identity, tolerances, level)`，其中
  `function(trade_date, sources)` 必须是模块级函数，只能用 `sources[dataset].open()`
  读取源字节，返回 `{"symbols", "values", "info"}`。
- 日期进程在生产解码**之前**，用同一份暂存字节算出独立参考，写成检查点
  `<输出根>/.reference_checkpoints/<scope>/<YYYYMM>/<YYYYMMDD>.parquet`。
  独立性不变：参考函数不经过适配器和分钟工具，只是与生成共用了同一份原始字节。
- 检查点绑定：源文件身份、参考函数所在包全部 `.py` 的 sha256、业务 identity、指标类型。
  任一不符即视为失效。
- `validate_published(group, config, output_roots, dates, reference, ...)`：
  读取已发布月文件，逐日、逐股票、逐分钟与检查点比对（整数与声明精确的指标逐位相等，
  其余按声明容差）。检查点缺失或失效时自动重扫源文件重算（`validation_rescan`），
  报告中逐日记录参考来源。校验通过后默认删除本次日期的检查点。
- 校验比对的是**已发布的最终月文件**，不是生成过程的中间结果。

### 4. 其他

- `provenance.source_contract` 的 Parquet 页脚按文件身份缓存，同一进程内不重复打开。
- `run_task_cli(..., reference=None)` 透传给执行器。
- 新增 `tests/test_source_sharing.py`。

## 发布前交叉评审修订（版本号不变）

- Windows 上按路径 `stat` 与按句柄 `fstat` 的 `ctime` 含义不同，句柄复核不再比较 `ctime`，避免把正常读取误报为文件变化；Linux 行为不变。
- 独立参考可用 `numpy.ma.MaskedArray` 的掩码声明期望为 NULL 的位置（整数指标只能用掩码，浮点指标也可继续用 NaN）；掩码随检查点保存并参与 NULL 位置比对，此前掩码被静默丢弃。
- `validate_published` 的指标选择为空时判失败并保留检查点，此前判通过并删除检查点。

## 兼容性

- 框架源码参与来源契约：1.2.4 发布的月文件不能被 1.3.0 以 resume 方式追加日期；
  已完整发布的月份不受影响，无需重算。
- 未提供 `reference` 的任务行为与 1.2.4 相同，只是读盘方式变为共享暂存。
- 非 Linux 或没有内存盘时自动使用进程私有 `buffer`；Windows 下无 `fcntl`，只有 `buffer`/`direct`。
- 暂存占用内存盘（计入内存），调度器分配内存时须扣除暂存预算。

## 清理约定

- 正常结束：`retain=False` 时最后一个持有者释放即删除；`retain=True` 时调度器结束时 `clear()`。
- 异常退出：锁自动释放，残留副本由下一次 `sweep(unheld=True)` 或 `clear()` 删除。
- 检查点在校验通过后删除；批次结束后 `.reference_checkpoints` 应为空并被移除。
