# Trans_To_Min 1.2.4 发布说明

发布日期：2026-11-11。本次是指标组性能与防误用的小版本修正，不运行生产数据任务。

## 一、已实现的修改

### 1. 股票全集单日只求一次（框架自动）

每个指标补齐 242 分钟前都要取“当天出现过的股票全集”（`MinuteMetric.symbol_union`）。
1.2.3 及以前每个指标各对整张逐笔表做一次 `dropna().unique()`；1.2.3 的 `symbols=` 要求业务
自己算对全集并显式传入，默认指标组不会受益。

1.2.4：

- 新模块 `trans_to_min.universe`：
  - `symbol_universe_scope()`：上下文管理器，开启单日缓存，退出即清空；
  - `frame_symbols(frame, dataset)`：返回一张输入表中实际出现的非空 symbol 集合，作用域内
    按表对象缓存。
- `MinuteMetric.symbol_union` 对每张声明输入调用 `frame_symbols` 再取并集，返回值与 1.2.3 相同。
- `runner._process_one_day` 与 `group_runner._process_one_group_day` 在单日计算外层开启作用域。
  因此单指标执行器、默认 `MinuteMetricGroup`、自定义指标组都自动受益，业务代码无需改动。
- 缓存粒度为单张输入表：声明输入组合不同的指标各自取并集，口径不变。

### 2. 缓存安全性

| 情况 | 处理 |
| --- | --- |
| 只缓存执行器登记的输入：读入后、交给业务前由 `symbol_universe_scope(inputs)` 登记 | 业务切片、复制或新建的表不缓存、不保护，每次计算 |
| 登记输入：同一表对象、同一 symbol 分类数组对象、行数不变 | 复用 |
| 替换 symbol 列（含 `loc[:, "symbol"] = ...` 整列赋值）、原地增删行 | 重新计算 |
| 原地改写单个 symbol（`iloc`/`at` 单格、直接写分类编码、经切片或编码视图写入） | 登记时 symbol 换成独立编码副本并设为只读：登记前已存在的视图只能写旧副本，不影响登记输入；之后派生的视图同样只读，写入报 `ValueError: assignment destination is read-only`；需要修改时先复制输入表 |
| 作用域退出 | 恢复登记时设为只读的编码数组为可写；原本就只读的保持只读；作用域内派生的视图仍只读 |
| 表对象被回收后新对象复用同一 id | 弱引用校验失败，重新计算 |
| symbol 不是分类列 | 不缓存，每次计算（适配器输出总是分类列） |
| 作用域外（测试、临时调用） | 不缓存 |
| 业务内部线程池 | ContextVar 不传入新线程，线程内不缓存，结果仍正确 |

### 3. 求集合提速

分类 symbol 列改为对分类编码 `bincount`，只取实际出现的分类值；未出现的分类与空值不计入，
与 `dropna().unique()` 结果相同。非分类列沿用原方法。

### 4. `finalize_aggregated_day(symbols=...)`

为兼容 1.2.3 保留，但改为强制核对：传入集合必须等于 `symbol_union(inputs)`，否则报
`ValueError` 并给出缺少/多出示例。作用域内核对几乎零成本。不再建议业务使用。

### 5. 发布前修订（版本号仍为 1.2.4）

首次部署后交叉评审发现：原地改写 symbol 且行数不变时，表对象与分类数组对象均未变化，
缓存会返回旧全集（例：应输出 242 行，实际 484 行）。修订为缓存期间共享编码只读（见上表），
并补“单格改写报错、整列赋值重算、退出恢复可写”回归；同时修正 README 中 1.2.3 段关于
“不核验显式全集”的过时描述。此前用 1.2.4 首版生成的测试数据不作为验收依据。

第二轮交叉评审又发现两处：缓存前取得的切片仍可绕过只读写入原表；先缓存切片再缓存原表时，
退出后切片可能遗留只读。原因是保护施加在任意被查询的表上，无法覆盖保护之前已存在的视图。
最终改为“执行器登记”：只有执行器读入后、交给业务前登记的输入才缓存和保护，登记时 symbol
换成独立编码副本（单日每表一次，2.29 亿行约百毫秒级），切片与复制不缓存、不保护；补“登记前
视图不能改动登记输入、作用域内视图不能写穿、切片退出后可写、未登记表不缓存不保护”回归，
并清理 README 第 8 节的旧描述。

## 二、实测

2026-09-28 委托（2.29 亿行，5210 只股票，服务器隔离副本）：

| 做法 | 耗时 |
| --- | --- |
| 原 `dropna().unique()` 单次 | 1.87 秒（13 个指标约 24 秒） |
| 新分类编码单次 | 1.38 秒 |
| 登记（编码副本）+ 作用域内 13 个指标合计 | 1.56 秒（其中登记 0.24 秒） |

两种方法结果一致。

## 三、保持不变

- 股票全集口径：声明输入中实际出现的非空 symbol，先于时间与方向筛选，含仅盘后出现的股票；
  不引入日频量价表等外部股票池。
- 分钟轴与边界、公式、NULL 规则、输出根与层级、四列 Schema、并行与月度发布、标准任务入口、
  来源门禁及 1.2.3 的无符号整数校验。

## 四、升级与历史结果

- 框架源码参与来源契约，1.2.3 输出不能直接 resume 为 1.2.4，旧凭证不改写。
- 业务若为 1.2.3 及以前写了“传只含 symbol 的小表”或 `symbols=` 的变通，升级后应删除，
  直接传执行器给的完整 inputs。
- 部署后须核对导入位置、运行时版本及安装元数据均为 1.2.4（命令同 1.2.3 发布说明）。

## 五、后续（不在本版）

几十上百个任务日频更新时，主要重复成本是各任务各自读取并解析同一天逐笔（每张表每任务
数十秒、内存峰值约 25G），不是股票全集。共享读取执行器（每天每表读一次，多任务依次或
共享只读内存计算，各自独立发布与核对）留待日频增量框架设计时另行出方案。
